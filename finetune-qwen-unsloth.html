Fine-tuning Qwen2.5-Coder with HuggingFace and Unsloth

Category: AI · Posted: 2026-05-24 · ~10 min read · Source code ↗
Article Info

This article walks through fine-tuning Qwen2.5-Coder-7B-Instruct on a Python instruction dataset using Unsloth and HuggingFace's TRL library. The goal was hands-on experimentation with QLoRA fine-tuning and to see how much a relatively small dataset shifts the model's output style.

The resulting model is published on HuggingFace as xtremecoder/Qwen2.5-Coder-7B-Instruct-Python-bnb-4bit.

1 Background

Fine-tuning a large language model used to require significant hardware — multiple high-end GPUs and days of training time. Two techniques have made it accessible on a single consumer or prosumer GPU:

  • QLoRA (Quantized Low-Rank Adaptation) — loads the base model in 4-bit precision to fit in limited VRAM, then trains only a small set of low-rank adapter matrices rather than the full parameter set. The adapters are trained in higher precision (bfloat16) even though the base weights are quantized.
  • Unsloth — a library that reimplements attention kernels and memory management for QLoRA training, cutting VRAM usage by ~30% and speeding up training roughly 2× compared to a naive HuggingFace + bitsandbytes setup.

The base model chosen is Qwen2.5-Coder-7B-Instruct, a code-focused instruction-tuned model from Alibaba's Qwen team. The 4-bit quantized version from Unsloth's HuggingFace org is used directly — it is already quantized and ready to load without a separate quantization step.

2 Setup

⚠ Hardware requirement This setup requires a CUDA GPU with at least ~16 GB VRAM. The configuration was tested on an RTX 5080 (16 GB). A T4 on Colab (15 GB) will work with slightly reduced batch sizes.
terminal
pip install unsloth trl transformers datasets bitsandbytes accelerate
finetune.py — imports
from unsloth import FastLanguageModel
from datasets import load_dataset
from trl import SFTTrainer, SFTConfig
import torch

Key constants used throughout the script:

finetune.py — config
MODEL_NAME     = "unsloth/Qwen2.5-Coder-7B-Instruct-bnb-4bit"
MAX_SEQ_LENGTH = 1024   # increase to 4096 if you have headroom
LORA_RANK      = 16     # 8–64; higher = more capacity, more VRAM
OUTPUT_DIR     = "./qwen-python-finetuned"

3 Loading the Model (4-bit QLoRA)

FastLanguageModel.from_pretrained is Unsloth's drop-in replacement for the standard HuggingFace loader. It handles 4-bit loading, flash attention patching, and rope scaling automatically.

finetune.py — load model
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name      = MODEL_NAME,
    max_seq_length  = MAX_SEQ_LENGTH,
    load_in_4bit    = True,   # essential for 16 GB VRAM
    dtype           = None,   # auto-detect (bfloat16 on Ampere+)
)

Setting dtype=None lets Unsloth pick the best floating-point format for the GPU. On Ampere and later architectures (RTX 3000+, A100, H100) this resolves to bfloat16, which has a wider dynamic range than float16 and is less prone to loss spikes during training.

4 Attaching LoRA Adapters

LoRA freezes the pre-trained weights and injects trainable rank decomposition matrices into specific layers. Only these adapter matrices are updated during training, dramatically reducing the number of trainable parameters while still allowing meaningful task specialisation.

finetune.py — LoRA config
model = FastLanguageModel.get_peft_model(
    model,
    r                        = LORA_RANK,         # rank of adapter matrices
    lora_alpha               = LORA_RANK * 2,    # scaling factor, 2× rank is common
    lora_dropout             = 0.05,
    target_modules           = [                  # attention + FFN projections
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    bias                     = "none",
    use_gradient_checkpointing = "unsloth",     # saves ~30% VRAM
    random_state             = 42,
)

The target_modules list covers both the attention projections (q/k/v/o_proj) and the feed-forward network projections (gate/up/down_proj). Targeting both is generally better than attention-only for code tasks where the FFN stores a lot of factual knowledge. With rank 16 this adds roughly 40 million trainable parameters on top of the frozen 7B base — about 0.6% of total weights.

ℹ Gradient checkpointing Setting use_gradient_checkpointing="unsloth" uses Unsloth's custom implementation, which recomputes activations during the backward pass instead of storing them. This trades compute for memory, reducing peak VRAM by around 30% with minimal speed penalty.

5 Loading the Dataset

The training dataset is iamtarun/python_code_instructions_18k_alpaca, a collection of ~18,000 Python coding instructions in Alpaca format (instruction, optional input, output).

finetune.py — load dataset
dataset = load_dataset(
    "iamtarun/python_code_instructions_18k_alpaca",
    split="train"
)

# Schema: ['instruction', 'input', 'output', 'prompt']
print(dataset.column_names)
print(dataset[0])

The dataset includes a pre-built prompt column formatted for Alpaca-style completion, but since Qwen2.5-Instruct uses ChatML rather than Alpaca format, this column is ignored and the examples are reformatted manually.

6 Formatting for ChatML

Qwen2.5-Instruct was trained with the ChatML template, which wraps each turn in <|im_start|> / <|im_end|> markers. Using the tokenizer's apply_chat_template method ensures the special tokens are inserted correctly without manual string construction.

finetune.py — format_example
def format_example(example):
    user_content = example["instruction"]

    # some examples include an additional input field
    if example.get("input", "").strip():
        user_content += f"\n\n### Input:\n{example['input']}"

    messages = [
        {
            "role": "system",
            "content": (
                "You are an expert Python programmer. "
                "Write clean, efficient, well-commented Python code."
            ),
        },
        {"role": "user",      "content": user_content},
        {"role": "assistant", "content": example["output"]},
    ]

    text = tokenizer.apply_chat_template(
        messages,
        tokenize             = False,
        add_generation_prompt = False,  # False during training
    )
    return {"text": text}

dataset = dataset.map(format_example, remove_columns=dataset.column_names)

# 95/5 train/eval split
split    = dataset.train_test_split(test_size=0.05, seed=42)
train_ds = split["train"]
eval_ds  = split["test"]

Setting add_generation_prompt=False during training is important — during training the full assistant turn is already included in the example, so no generation prompt is needed. At inference time this is flipped to True so the model knows to start generating a response.

7 Training Configuration

finetune.py — SFTConfig
training_args = SFTConfig(
    output_dir = OUTPUT_DIR,

    # batching
    per_device_train_batch_size  = 2,
    gradient_accumulation_steps  = 4,   # effective batch size = 8
    num_train_epochs             = 1,

    # optimizer
    learning_rate      = 2e-4,
    lr_scheduler_type  = "cosine",
    warmup_ratio       = 0.05,
    weight_decay       = 0.01,
    optim              = "adamw_8bit",  # saves VRAM vs fp32 Adam

    # precision — auto-select fp16 vs bf16
    fp16 = not torch.cuda.is_bf16_supported(),
    bf16 = torch.cuda.is_bf16_supported(),

    # logging
    logging_steps          = 10,
    save_strategy          = "epoch",
    eval_strategy          = "epoch",
    load_best_model_at_end = True,
    report_to              = "none",

    # sequence packing — combines short examples to fill context windows
    dataset_text_field = "text",
    max_seq_length     = MAX_SEQ_LENGTH,
    packing            = True,
)

A few choices worth noting:

  • Gradient accumulation — with a physical batch size of 2 and 4 accumulation steps, the effective batch size is 8. This simulates a larger batch without the VRAM cost.
  • AdamW 8-bit — bitsandbytes' 8-bit Adam stores optimizer states in 8-bit, roughly halving their memory footprint compared to the standard fp32 Adam states used by default.
  • Sequence packing — rather than padding all sequences to the same length and wasting compute on padding tokens, packing concatenates multiple short examples together to fill each context window. This typically improves GPU utilisation and speeds up training.
  • One epoch — with 18k examples this is enough to meaningfully shift the output style without overfitting on a small dataset.
finetune.py — train
trainer = SFTTrainer(
    model         = model,
    tokenizer     = tokenizer,
    train_dataset = train_ds,
    eval_dataset  = eval_ds,
    args          = training_args,
)

trainer_stats = trainer.train()
print(f"Done! Runtime: {trainer_stats.metrics['train_runtime']:.0f}s")

# save LoRA adapters only (lightweight — not the full model)
model.save_pretrained(OUTPUT_DIR)
tokenizer.save_pretrained(OUTPUT_DIR)

8 Exporting and Pushing to Hub

8.1 GGUF export for llama.cpp / Ollama

After training, the adapters can be exported directly to GGUF format for use with llama.cpp or Ollama. Unsloth handles the merge-and-quantize step in one call:

finetune.py — GGUF export
model.save_pretrained_gguf(
    OUTPUT_DIR + "-gguf",
    tokenizer,
    quantization_method = "q4_k_m",  # good quality/size tradeoff
)

8.2 Pushing to HuggingFace Hub

A separate hf_push.py script reloads the saved adapters and pushes them to HuggingFace Hub. The model is published under the xtremecoder HuggingFace account:

hf_push.py
from unsloth import FastLanguageModel

MAX_SEQ_LENGTH = 1024

def push_model(local_model_name: str, hf_model_name: str):
    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name     = local_model_name,
        max_seq_length = MAX_SEQ_LENGTH,
        load_in_4bit   = True,
    )
    model.push_to_hub(hf_model_name)

push_model(
    local_model_name = "./qwen-python-finetuned",
    hf_model_name    = "xtremecoder/Qwen2.5-Coder-7B-Instruct-Python-bnb-4bit",
)

9 Results and Observations

Comparing the original and fine-tuned models side by side using load_model.py reveals a clear shift in output style. The fine-tuned model drops explanatory prose and generates code directly, mirroring the output field style in the training dataset.

9.1 Example: "Create a hello world program"

Original Qwen2.5-Coder-7B-Instruct Fine-tuned model

Certainly! Below is a simple "Hello, World!" program in Python:

print("Hello, World!")

To run this program, you can save it to a file with a .py extension and execute it using a Python interpreter…

 
print("Hello World!")

The broader pattern across many prompts:

  • No preamble or explanation — the fine-tuned model outputs code immediately, without "Certainly!" or surrounding commentary. This is a direct result of the training data's output field containing only code.
  • Different code style — the generated code is sometimes more concise and occasionally uses different approaches than the base model. In some cases it is more efficient; in others it introduces subtle correctness issues.
  • Reduced verbosity — inline comments and docstrings appear less frequently than in the base model's output.
⚠ Correctness trade-off The fine-tuned model's code is occasionally subtly wrong in ways the base model is not — likely a consequence of the training dataset's quality rather than the fine-tuning process itself. For production use the dataset would need careful filtering or the model would need evaluation on a held-out correctness benchmark.

9.2 Running the comparison yourself

load_model.py
from unsloth import FastLanguageModel

ORIGINAL = "unsloth/Qwen2.5-Coder-7B-Instruct-bnb-4bit"
MAX_SEQ_LENGTH = 1024

def generate_output(model_name: str, user_content: str) -> None:
    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name, max_seq_length=MAX_SEQ_LENGTH, load_in_4bit=True
    )
    FastLanguageModel.for_inference(model)  # switch to faster inference mode

    prompt = tokenizer.apply_chat_template(
        [
            {"role": "system",  "content": "You are an expert Python programmer."},
            {"role": "user",    "content": user_content},
        ],
        tokenize=False, add_generation_prompt=True,
    )

    inputs  = tokenizer(prompt, return_tensors="pt").to("cuda")
    outputs = model.generate(
        **inputs, max_new_tokens=8144,
        temperature=0.2, do_sample=True,
    )
    response = tokenizer.decode(
        outputs[0][inputs["input_ids"].shape[1]:],
        skip_special_tokens=True
    )
    print(f"\n── {model_name} ──")
    print(response)

prompt_msg = "Create a calculator program"
generate_output(ORIGINAL, prompt_msg)
generate_output("./qwen-python-finetuned", prompt_msg)

Note FastLanguageModel.for_inference(model) — this call patches the model with Unsloth's optimised inference kernels, which are separate from the training-time kernels and give a further speed boost at generation time.
